## 시작 조건

- 대상 영역의 테스트가 **전부 녹색**이어야 시작한다. 아니면 테스트 복구가 먼저다.
- 이 작업의 선언: "동작은 바뀌지 않는다." 공개 API·응답 계약·Schema가 바뀐다면 이 Skill이 아니라 `api-contract-sync`/`db-migration` 대상이다.

## 작업 순서

1. 범위를 파일·모듈 단위로 좁게 정의한다.
2. 대상의 테스트 커버가 부족하면 현재 동작을 고정하는 특성화 테스트를 먼저 추가한다.
3. 작은 단계로 변경하고 단계마다 테스트를 돌린다. 커밋도 단계 단위로 한다.
4. 리팩터링 중 발견한 기능 개선·버그는 이 MR에 넣지 않는다 — 버그는 별도 작업 키, 개선은 `improvement-backlog`로.

## 완료 기준

- 변경 전후 테스트 결과가 동일하게 통과한다(커버리지 게이트 포함).
- diff를 보고 "동작 변경 없음"을 리뷰어가 확인할 수 있다.

## 금지

- 리팩터링과 기능 변경을 같은 커밋·MR에 섞기
- 테스트 없는 코드를 테스트 추가 없이 구조 변경
