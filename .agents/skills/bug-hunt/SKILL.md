## 먼저 읽을 근거

1. 증상 재현 경로와 실제 오류 출력(추측 금지, 원문)
2. 관련 코드·테스트와 최근 변경(git log)
3. 해당 작업 키의 Work Log

## 작업 순서

1. **재현을 최소화한다.** 가능하면 실패하는 테스트로 재현을 고정한다. 재현 불가면 재현 조건 수집이 먼저다.
2. 가설을 나열하고 **한 번에 하나씩** 검증한다. 각 가설은 로그·디버거·테스트로 확인하고 결과를 기록한다.
3. 원인을 코드 근거로 설명할 수 있을 때까지 **수정하지 않는다.** 여러 곳을 동시에 바꾸지 않는다.
4. 수정 후: 재현 테스트가 수정 전 실패 → 수정 후 통과함을 확인하고 회귀 테스트로 남긴다.
5. 10분 이상 걸렸거나 접근이 두 번 이상 실패했으면 checkpoint(ERROR/ATTEMPT)로 기록하고, 재사용 가치가 있으면 `troubleshooting-record`로 정리한다.

## 완료 기준

- 원인 설명이 추측이 아니라 재현 가능한 근거로 되어 있다.
- 재현 테스트가 저장소에 남아 있다.

## 금지

- 원인 불명 상태에서 "고쳐진 것 같습니다" 보고
- 증상만 사라지게 하는 우회(예: 예외 삼키기, 타이밍 sleep)를 근본 해결로 표기
