# ADR-001: AI 출력 스타일·워크플로 강제 방식 — 하네스 규칙 vs 개인 플러그인

- 상태: **논의 대기** (팀 회의 안건)
- 작성: 2026-08-19
- 관련: `CLAUDE.md`(하네스 우선 원칙), `AGENTS.md`(최소 변경 규칙), ponytail·superpowers 류 플러그인

## 배경

"최소한의 코드", "TDD·계획·검증 절차" 같은 AI 작업 방식을 강제하는 방법이 두 갈래다.

1. 저장소 하네스 문서(AGENTS.md·Skill)에 규칙으로 명시 — 현행
2. 각자 ponytail·superpowers 같은 플러그인을 설치해 세션 차원에서 강제

현재는 1을 기본으로 하고, 플러그인은 개인 자유 + 충돌 시 하네스 우선으로 운영 중이다. 팀 전체 방침을 확정해야 한다.

## 선택지

### A. 하네스 규칙만 (현행 유지)

- 장점: 전원에게 동일 적용(설치 불요), 규칙의 단일 원본이 저장소, 버전 관리·리뷰 가능, 추가 토큰 소모 없음
- 단점: 강제력이 AI의 문서 준수와 리뷰·훅에 의존 (세션 차원 하드 강제는 아님)

### B. 플러그인 팀 표준화 (전원 설치 의무)

- 장점: 세션마다 자동 적용, 문서를 안 읽어도 스타일이 잡힘
- 단점: 전원 설치·버전 동기화 부담, 개인 환경 차이로 인한 사고(과거 graphify 개인 경로 커밋 사례), 하네스와 규칙 이중화·충돌 가능, 플러그인 절차 자체가 토큰을 추가 소모(superpowers), 강제 수단이 저장소 밖으로 나감

### C. 절충 (권장 기본값)

규칙의 원본은 하네스(A), 플러그인은 개인 자유. 단 세 가지를 못 박는다:

1. 플러그인 지시가 하네스와 충돌하면 하네스를 따른다 (`CLAUDE.md`에 이미 명시)
2. 플러그인 설정·훅·산출물을 팀 저장소에 커밋하지 않는다
3. 플러그인이 하네스 필수 기록(Work Log, MR 검증 항목)을 축약·생략하게 만들면 사용을 중단한다

## 결정을 위한 질문 (회의에서 확인)

1. 전원에게 특정 플러그인 설치를 강제할 수 있는가? (설치 못 하거나 안 하는 사람이 생기면 B는 성립하지 않음)
2. 플러그인 규칙과 하네스 규칙이 어긋날 때 무엇이 이기는가에 모두 동의하는가?
3. 플러그인 버전·설정 관리를 누가 담당하는가?
