## 허용 조건 (모두 만족해야 함)

1. 문서·주석·오타 수정 또는 dev 빌드/CI를 깨뜨린 원인의 즉시 수정이다.
2. 변경이 30줄 이하, 1커밋이다.
3. API·DB·의존성·설정 계약 변경이 없다.
4. 커밋 컨벤션(`<gitmoji> <type>: 요약`)을 지킨다.

## 작업 순서

1. 위 조건 4개를 확인한다. 하나라도 아니면 중단하고 브랜치 + MR 절차로 전환한다.
2. 최신 `dev`에서 직접 수정하고 커밋한다.
3. push 후 dev Pipeline이 녹색인지 확인한다.
4. Pipeline이 실패하면 즉시 `git revert`로 되돌리고, 원인은 정식 작업 키로 처리한다.

## 완료 기준

- dev Pipeline 녹색.
- 수정 내용이 커밋 메시지만으로 설명된다(별도 Work Log 불필요).

## 금지·승인

- `main` 직접 push는 예외 없이 금지한다.
- 이 절차로 기능 코드를 넣지 않는다. "작으니까"는 기능 변경의 허용 사유가 아니다.
- 같은 파일에 하루 2회 이상 hotfix가 반복되면 중단하고 정식 Issue로 전환한다.
