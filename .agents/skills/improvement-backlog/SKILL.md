## 원칙

지금 작업 키의 범위를 벗어나는 개선은 **구현하지 말고 기록한 뒤 원래 작업을 계속한다.** "하는 김에"는 스코프 폭주의 시작이다.

## 작업 순서

1. `.agent/backlog/<발견한 WORK_KEY>-<kebab-slug>.md` 파일을 만든다.
2. 다음 항목을 채운다.

```markdown
# <제안 한 줄 요약>
- 발견 맥락: <어떤 작업 중, 어떤 코드·쿼리에서>
- 제안 내용: <무엇을 어떻게>
- 예상 효과: <추정이면 추정이라고 명시>
- 착수 조건: <예: DB 엔진 확정, EC2 지급, 측정 데이터 확보, 없음>
- 측정 계획: <성능 제안이면 필수 — EXPLAIN, 부하테스트, 메트릭 등>
```

3. 원래 작업으로 복귀한다. backlog 기록은 Work Log checkpoint 대상이 아니다.

## 승격

- Jira 활성화 후 스프린트 계획에서 backlog 파일을 검토해 Issue로 승격하고, 승격된 파일은 Issue 링크를 남긴 뒤 삭제한다.
- 성능 관련 항목(인덱스, 캐시, 쿼리)은 측정 계획 없이 승격하지 않는다.

## 금지·승인

- backlog에 기록했다는 이유로 현재 MR에 해당 변경을 끼워 넣지 않는다.
- 인덱스·Schema가 필요한 제안이라도 이 단계에서는 migration을 만들지 않는다(착수 시 `db-migration` Skill).
