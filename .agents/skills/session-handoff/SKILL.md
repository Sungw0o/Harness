## 언제 쓰는가

- 작업이 미완료인 채 세션을 끝내기 전
- 컨텍스트가 길어져 새 세션으로 갈아탈 때
- 같은 작업 키를 다른 사람·다른 AI가 이어받을 때

## 작업 순서 (남길 때)

1. `.agent/handoff/<WORK_KEY>.md`에 다음을 작성한다. 이 파일은 최신 스냅샷이므로 덮어써도 된다.

```markdown
# <WORK_KEY> 인수인계 — <날짜>
- 완료: <끝난 것, 검증 상태 포함>
- 미완료: <남은 것, 다음에 바로 할 첫 단계>
- 시도했다 실패한 것: <같은 삽질 반복 방지 — 접근과 실패 이유>
- 함정·주의: <건드리면 안 되는 것, 알아낸 제약>
- 검증: <어디까지 돌려봤는지, 안 돌려본 것>
```

2. 의미 있는 결정·실패는 Work Log checkpoint에도 append한다(원본은 JSONL).

## 작업 순서 (이어받을 때)

1. `.agent/worklogs/<WORK_KEY>.jsonl`과 `.agent/handoff/<WORK_KEY>.md`를 먼저 읽는다.
2. "시도했다 실패한 것"의 접근을 반복하지 않는다.
3. 이어받은 직후 현재 코드 상태와 노트가 일치하는지 `git status`·테스트로 확인한다.

## 완료 기준

- 작업이 FINISH되고 MR이 병합되면 handoff 파일을 삭제한다. 재사용 가치가 있는 내용은 troubleshooting-record로 옮긴다.
